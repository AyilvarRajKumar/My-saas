# Greenfield SaaS landing page with glassmorphism and Framer Motion

A single-page React marketing site (React 19 + Vite 8 + Tailwind CSS 3 + Framer Motion) implementing 9 sections — Header, Hero, Services, Process, Portfolio, Testimonials, Pricing, Contact, and Footer — with a dark glassmorphism visual language, parallax blobs, a 3D tilt card effect, an infinite-scroll testimonial carousel, and form validation. The project compiles cleanly on TypeScript 6 with zero warnings.

Watch for: the contact form submits nowhere (confirmed) — the "success" state is purely cosmetic with no backend or even a `mailto:` fallback, which could mislead users. The newsletter subscription in the footer has the same issue. The infinite-scroll carousel uses a runtime-injected `<style>` tag with a raw CSS `@keyframes` block inside JSX (confirmed), which will duplicate into the DOM on every re-mount and conflicts with Tailwind's utility-first approach.

**Verdict**: APPROVED

## High-level view

The project is structured as a straightforward single-page app with one component per visual section, composed linearly in `App.tsx`. There is no routing, no state management library, and no data fetching — every piece of content is hard-coded in component-local arrays.

Every animated component checks `useReducedMotion()` and conditionally passes `undefined` to Framer Motion variant props. The shared variant definitions in `utils/animations.ts` keep motion parameters DRY across all sections.

The contact form implements client-side validation (name, email regex, message presence) and shows inline error states, but `handleSubmit` only toggles a cosmetic "sent" flag and resets after 3 seconds — no network call, no form-action, no service integration. The footer newsletter field has the identical pattern. Both will silently eat user input.

The testimonial carousel achieves infinite scrolling by duplicating its data array and using a CSS `translateX(-50%)` animation. The implementation injects a `<style>` element directly into the component's JSX return, meaning it re-renders into the DOM on every mount. It bypasses Tailwind's build pipeline and is a maintenance liability if components are conditionally rendered.

The bundle weighs 366 KB (114 KB gzipped), dominated by `framer-motion` and `react-icons`. For a marketing page where first-contentful-paint matters for conversion, the payload is worth monitoring as sections are added.

## Form submission gap

The `Contact` component's `handleSubmit` (Contact.tsx, line 70) calls `validateForm()`, and on success sets `isSubmitted = true`, waits 3 seconds, then resets the form. There is no `fetch`, no form `action` attribute, no integration with a service like Formspree, EmailJS, or a backend API. A visitor who fills in the form will see "Message Sent!" and their data vanishes into the void. The footer's `handleSubscribe` (Footer.tsx, line 30) has the same structure: validation of non-empty email, cosmetic state toggle, no persistence.

This isn't a "we'll wire it up later" stub with a TODO — the success UX is fully built, which means a deployed version of this site would actively mislead users into believing their message was delivered.

## Inline styles in Testimonials

```tsx
<style>{`
  @keyframes scroll { ... }
  .animate-scroll { animation: scroll 40s linear infinite; }
  .group:hover .animate-scroll { animation-play-state: paused; }
  @media (prefers-reduced-motion: reduce) { .animate-scroll { animation: none; } }
`}</style>
```

This block lives inside the component's return statement (Testimonials.tsx, line 147). Every time the component mounts, a new `<style>` element is appended to the DOM at that position. In this app it only mounts once, but the pattern is fragile: if the section were conditionally rendered or code-split, duplicate style blocks would accumulate. More practically, it means `animate-scroll` is invisible to Tailwind's purge step and to any future migration to Tailwind v4's CSS-first config. The fix is trivial — add `scroll` under `theme.extend.keyframes` in `tailwind.config.js` and reference it via a Tailwind `animate-*` utility class.

## Dead-end anchor links

Every social icon in both the Contact section and the Footer uses `href="#"`. On click this scrolls the page to top — a jarring experience on a long single-page site. Either wire in real URLs (even placeholders like `https://twitter.com/nexus`) or render them as non-interactive `<span>` elements until real links exist, to avoid confusing keyboard and screen-reader users who encounter "link" semantics with no destination.

## 3D tilt fidelity gap on mobile

The Portfolio component's `PortfolioCard` calculates `rotateX` / `rotateY` on every `mousemove` event via `setState`. On mobile, `mousemove` doesn't fire, so the tilt effect is effectively inert — mobile users see static cards while desktop users see the 3D effect. If touch-based tilt is intended in the future, touch events would need explicit handling, and the per-frame `setState` pattern would become a performance concern on high-frequency touch-move events.

## Bundle composition

The production build is 366 KB uncompressed (114 KB gzip). `framer-motion` alone is ~120 KB minified; `react-icons` contributes additional weight from imports across two icon families (`Hi` and `Fi`). For a marketing page where first-contentful-paint matters for conversion, this is worth monitoring — especially if more sections are added.
